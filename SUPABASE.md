# Публикация игр в Genially

Редактор и плеер остаются на GitHub Pages. «Мои игры», черновик и экспорт проекта по-прежнему работают локально. Публикация берёт последнюю **сохранённую** версию проекта.

## Подключение владельцем

1. В Supabase откройте **Project Settings → API**. Скопируйте Project URL и **Publishable key** (`sb_publishable_…`). Внесите их в `publication-config.js` и разверните эту версию редактора на GitHub Pages. Это публичные значения.
2. В **Authentication → Users** скопируйте UUID уже созданной учётной записи владельца. В **Edge Functions → Secrets** добавьте `BINGO_OWNER_UID` со значением UUID. Оставьте открытые регистрации и анонимный вход выключенными. Пароль владелец вводит только в форму входа опубликованного редактора. Секретный ключ Supabase используется только в окружении Edge Functions.
3. В локальной копии репозитория с установленным Supabase CLI войдите в свой аккаунт и подключите существующий проект. `PROJECT_REF` — идентификатор из URL `https://PROJECT_REF.supabase.co`.

   ```sh
   supabase login
   supabase link --project-ref PROJECT_REF
   supabase db push
   supabase functions deploy publish-game --no-verify-jwt
   supabase functions deploy read-game --no-verify-jwt
   ```

   Если CLI запрашивает авторизацию или пароль базы, вводите их в своей среде. Не добавляйте пароль, административный токен или `service_role` в репозиторий. Миграцию можно также применить в SQL Editor, выполнив файл из `supabase/migrations` один раз. Для обеих функций отключена проверка JWT на шлюзе. Функция публикации проверяет токен через Supabase Auth и сравнивает UUID с `BINGO_OWNER_UID` сама.
4. Проверьте в Dashboard таблицу `game_publications` с RLS и приватный бакет `game-publications`. На бакете действует ограничительная политика для `anon` и `authenticated`. Разрешать этим ролям доступ к таблице или бакету отдельно не требуется.
5. Откройте «Встраивание в Genially» и войдите как владелец. Сохраните проект и нажмите «Опубликовать / обновить» в «Моих играх» или «Опубликовать» в разделе Genially. Скопируйте iframe **1280×720** в «Вставка → Другое» и проверьте его в опубликованной презентации.
6. В приватном окне проверьте ссылку без входа. Обновите сохранённый проект и убедитесь, что ссылка ведёт на новую версию. Затем снимите игру с публикации и повторно опубликуйте. Ссылка должна остаться прежней, а копия проекта должна получить свою.

## Хранение и ограничения

- Сервер хранит постоянный UUID игры отдельно от UUID версии. Новые медиа сначала записываются в отдельный каталог версии. Переключение происходит только после проверки, что все заявленные файлы загружены. Более позднее обновление или снятие с публикации блокирует завершение устаревшей операции.
- Публичная функция принимает UUID игры и выдаёт только активный снимок, включая ссылки для скачивания со сроком **5 минут**. После снятия с публикации новые загрузки игры блокируются. Открытая игра может продолжить работу, поскольку уже получила свои данные.
- Лимиты приложения — **50 МБ на файл, 100 МБ на снимок, 500 медиафайлов**. Плеер загружает медиа при открытии игры, пакетами до шести файлов. Проверяйте вес снимка перед публикацией проектов с длинными записями. На Free суммарное хранилище ограничено 1 ГБ.
- Каталоги старых и прерванных версий остаются в бакете. Для освобождения места остановите публикации на время обслуживания, проверьте актуальные `id/revision` в `game_publications` и удалите остальные каталоги через **Storage**. Дайте истечь ранее выданным ссылкам на загрузку и скачивание. Удалять записи напрямую из `storage.objects` нельзя.
- Удаление локального проекта из «Моих игр» и снятие игры с публикации — отдельные действия. Перед удалением локального проекта снимите его с публикации, если публичная ссылка больше не нужна.
